## 1. 피치와 비전

**피치:** 레서판다 럭키와 별빛 통신망을 한 칸씩 이어 가는 우주 탄막 비행. 음악은 판의 흐름에 맞춰 바뀌고, 격추돼도 2초 뒤면 다시 날 수 있다.

**비전:** 지금 있는 재료를 하나의 줄로 꿴다. 플레이 규칙을 바꾸는 새 장치는 운영자가 승인한 것만 넣는다.

| 명작의 조건 | 지금 | 목표 |
|---|---|---|
| 첫 30초에는 한 가지만 가르친다 | 시작 화면 선택지 약 15개, 6초 만에 위성 미션 | 첫 판은 피하기 → 스치기 → 미션 순서. 25초 전에는 미션이 없다. 시스템 단계 개방은 승인 대기 |
| 재시도 비용이 0에 가깝다 | 사망 → 카드 → 탭 → 인트로 | 길게 누르면 2초 안에 재비행 |
| 죽어도 억울하지 않다 | 처벌 4중첩. 예고 형식이 위협마다 다르다 | 예고 문법 하나, 실제 판정 반경(11px) 표시, 편한 비행 |
| 음악이 곧 긴장이다 | 고정 mp3 2곡 | 막마다 키·코드가 다른 시퀀서. SURGE·BREATHER·보스·피버·마지막 하트에 맞춰 **미리 스케줄된** 층 전환 |
| 끝까지 볼 수 있다 | 343초 도달 1%. 4·5막은 사실상 아무도 못 본다 | 도달한 막부터 출발하는 연습 비행 |
| 공유하고 싶은 장면이 있다 | 공유는 텍스트뿐 | GL 배경(중력렌즈), 결과 PNG, 데일리 이모지 한 줄 |

**세 원칙:** ① 꿴다. 플레이 규칙 변경은 승인을 받는다 ② 난이도는 그대로 두고 억울함만 줄인다 ③ 글자 대신 소리·빛·모양으로 알린다.

## 3. 공통 작업 규약 (모든 패키지 필독)

| 항목 | 규칙 |
|---|---|
| 워크트리 | `git worktree add C:\code\python\luckyplz_wt\mpN -b fx-mpN main` (MP0 병합 후의 main). `.claude\` 아래에는 만들지 않는다(권한 프롬프트 문제) |
| 내 코드 위치 | MP0가 만들어 둔 **자기 스텁만** 쓴다. JS는 `<script>` 블록 안 `/*<sz:mod:mpN>*/ … /*</sz:mod:mpN>*/`, CSS는 `/*<sz:css:mpN>*/`, HTML은 `<!--<sz:html:mpN>-->` |
| 스텁 블록 형식 | **블록마다 IIFE**로 감싸고 밖으로는 `window.SZMPn`만 노출한다. 블록 끝에서 `SZMPn.ok = true`. 클래식 스크립트의 최상위 `let`·`const`는 전역 렉시컬 스코프를 공유하므로, 이름이 하나라도 겹치면 뒤 블록 전체가 소리 없이 죽는다. 게이트가 센티널 8개를 확인한다 |
| 기존 코드 수정 | 패키지 표의 **소유 구역**에 적힌 함수·줄만 고친다. 나머지와의 연결은 `SZE.on(...)` 구독과 MP0 API(`SZSTART`·`szRunKind`·`szWarpTo`·`szRAF`·`SZGL`·`szShipSkinHook`)로만 한다 |
| 결정성 | **`rand`·`randH`·`randD` 호출 추가·삭제·순서 변경 금지.** 새 배치는 `szZoneRng(seed,'mpN',z)` 서브스트림이나 `_szU('mpN',z,k)` 해시, 표시는 `Math.random`. 게이트 det는 패키지마다 nR·nH·nD 호출 수가 기준선과 같은지 비교한다 |
| 킬스위치 | 패키지 기능은 전부 `SZ_FLAGS.mpN`이 참일 때만 돈다. `?mpN=0`으로 끄면 경로가 MP0 병합 직후와 같아야 한다(게이트 `flags0`) |
| 금지 연출 | 캔버스·`#canvasWrap`·조상 요소의 전체 오프셋(흔들림), 번쩍임 α>0.12, S등급 반응(스침·픽업)에 정지 넣기 |

4. **비행감 — 기존 값 조정만:** 뱅크(`szBank` ±0.34, 5프레임 뱅크 아틀라스 18472–18528)와 SZ3 RCS(`lastRcs`)는 이미 있다. 진공 원칙상 뱅크를 키우지 않는다. RCS 퍼프 타이밍·밝기와 고속 잔상(3프레임, 표시 전용)만 조정한다.
5. `SZGL.snapshot(ctx2d)`: 호출 시점에 GL 배경을 한 번 더 그려 `drawImage`로 넘긴다.

**수용 기준**

**방식:** 위험물 수열이 바뀌므로 코스 버전 `SZ_CV`를 올린다(구 도전장 링크는 구 cv로 계속 연다). 패턴마다 ① 예고 → ② 안전 통로가 보이는 발사 → ③ 쉬는 박자의 3단 문법. 보스마다 페이즈 2개 이상. ibot 1,000시드에서 보스 존 생존율이 기준선 허용폭 안이어야 하고, 보스 존 사망 위치 히트맵으로 '피할 수 없는 자리' 0을 확인한다.

이 패키지는 난이도 회귀(지금까지 4번 왕복)의 위험이 가장 크다. 그래서 웨이브 1–3과 분리하고, 승인 전에는 설계 문서(패턴 스케치·ibot 시뮬)만 만든다.

## 6. 성공 지표와 측정

**ibot 난이도 판정(모든 병합 공통):** 1,000시드. **중앙값 생존시간이 기준선 ±N초** 그리고 **부트스트랩 95% CI가 기준선 CI와 겹칠 것.** N = max(8초, MP0이 잰 실행 간 중앙값 차이 ×2). 수열이 갈라지는 패키지(MP5 스침 → BEAM → 보급)는 사실상 재표본이라 차이의 표준편차가 커지므로, 184초 도달률·343초 도달률 같은 꼬리 지표는 **참고만** 하고 판정에 쓰지 않는다. 200코스에서 도달률 36%의 표준오차는 약 3.4%p이고, 343초 도달 1%는 200판 중 2판이다.

## 9. 비평 처리

v1에 대한 코드 대조 비평(main 4d9f199 기준) 항목별 처리. 근거 줄 번호는 이번에 다시 대조해 확인했다(20441–20492 rng, 18873 `elapsedMs`, 19086–19133 충돌·피격, 18091 힌트 R=11, 14951·13764 번쩍임, 18946·18957 따라잡기, 20598–20614 스케줄러, 22311 tier, 24165·24203·24389·17324·25516 주입자, 23560·23570·24000·24385·24396 기록, gate 314·331 det).

### 치명
1. **randH는 해시가 아님** — **반영.** 2-1 표·3장 규약 수정, det에 nR·nH·nD 호출 수 비교 추가.
2. **데스봄 유예 전제 오류** — **반영.** 논리 시간이 흐른다는 점, 마지막 하트 즉시 game over, 누르지 않은 판 55ms 차이, det가 충돌 경로를 안 탄다는 점을 모두 인정. `pendingHit` 설계·아이템 보유 시에만 유예·확정 시점 `hit` 발행으로 고쳐 **8장 A1(승인 대기)**로 옮겼고, 충돌 경로 하네스 `hitpath`는 MP0에 넣었다.
3. **AudioContext 1개 불가** — **반영.** 기본안은 (b) "≤2개". (a) `LPAudio.ctx()`는 공용 JS 변경이라 8장 B1. `createMediaElementSource`는 쓰지 않고 `<audio>`를 폴백으로 유지. 오디오 세션 정책은 "설정하지 않음"으로 명시하고 B2와 실기기 확인 목록에 넣었다.
4. **시작 화면 소유 구역 불일치** — **반영.** MP0에 `SZSTART` 슬롯(멱등)과 주입자 4곳 전환, `addStartButton` 출력 모양은 MP1 소유. 데일리 칩은 시작 화면에 남는다고 MP1에 명시.
5. **공식 기록 판정 소유자 없음** — **반영.** MP0 `szRunKind()`, 4개 저장 경로. `szx_daily`는 필드 추가 + 덮어쓰기 버그 지점(24396) 병합 처리, MP7 소유에 23540–23600 추가, `chUrl` 위치 정정.
6. **연습 비행 운석 폭주** — **반영.** MP0 `szWarpTo(z)`, MP6 수용 기준에 스폰 수·프레임 최대 추가.
7. **noshake 즉시 FAIL·측정 오류** — **반영.** 번쩍임 2곳 0.12 정리를 MP0의 명시적 예외로, 측정은 3방식으로 교체.

### 높음
8. **MP8 GL 실현성** — **반영(a–g 전부).** GL 컨텍스트 1개를 2D 아래에, 블룸은 GL 입자에만, 실기기 성능 기준·GL 실행 표시, 무상태 입자, Worker 대신 프로파일 먼저·프레임 분할 미리 굽기, 120Hz 솎아내기는 측정 p50 ≤10ms 조건·`szRAF` 통일, 비행감은 기존 값 조정. 이에 따라 MP8을 a/b/c로 나눴다(비평 19).
9. **판정점 2px는 실제와 다름** — **반영.** 11px 링, 기본 꺼짐, 기본 켜짐은 8장 A3. 판정 축소는 하지 않는다.
10. **편한 비행 dt 지점 오류** — **반영.** `_worldDt` 배율 + assist 판 스폰 간격 ÷0.85.
11. **ibot ±2%p는 잡음보다 좁음** — **반영(부분 조정).** 병합 판정은 1,000시드·중앙값 ±N초·부트스트랩 CI. 단, 패키지 안 반복 확인은 실행 시간 때문에 200시드를 유지한다(판정에는 쓰지 않음). N은 MP0이 실행 간 차이를 실측해 정한다.
12. **재시작 스와이프 충돌·synth 측정 오류** — **반영.** 스와이프 삭제, restart 게이트는 실제 시간/CDP 가상시간.
13. **웨이브 2 숨은 의존** — **반영.** MP0에 `SZGL.snapshot`·`szShipSkinHook` 스텁. 도색 동기화는 `SZX.myLivery` 형식 안에서 값만 추가. MP8b를 웨이브 3으로 옮겨 MP7 PNG·MP6 도색이 스텁 위에서 먼저 돌고 MP8b가 실제 구현을 채운다.
14. **스텁 블록 렉시컬 충돌** — **반영.** IIFE·`window.SZMPn`·센티널 게이트.
15. **예고 앞당기기 불가** — **반영.** 위치 사전 예고는 하지 않는다. peek 기반 시각·종류 예고와 종류별 표를 MP3에 넣었다. 추가 확인: 7개 `spawn*` 함수 머리 45줄을 grep 했더니 `spawnWave`를 뺀 6개에서 `player.` 참조가 나왔다. 이 함수들은 발사 순간의 기체 위치를 읽을 가능성이 높아 위치 예고를 미리 할 수 없다. MP3 착수 때 함수별로 다시 확인한다. 비평이 제안한 "미리 뽑아 큐에 저장" 방식은 스케줄러 시계를 앞당기는 것과 같아 det `ft` 기록이 바뀌므로 이번 범위에서는 파도에 대한 스파이크로만 남겼다.

1. **위협 패턴 설계** — **부분 반영.** MP9로 설계했지만 웨이브 4·운영자 승인으로 분리했다. 이유: 위험물 수열을 바꾸는 유일한 패키지라 코스 버전 변경이 필요하고, 직전 피드백("너무 어렵다")과 난이도 왕복 4회 이력상 웨이브 1–3과 같은 시기에 섞으면 원인 분리가 안 된다.
