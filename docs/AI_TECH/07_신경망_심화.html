1

한 뉴런이 하는 일 — 구체 숫자로 끝까지 풀기

"신경망이 무엇을 한다"의 가장 작은 단위 — 뉴런 1개가 하는 계산을 끝까지 추적합니다. 이 작은 패턴이 수억 번 반복돼서 GPT, 자율주행, fab VM이 됩니다.

WHY · 왜 뉴런부터 시작하는가

"전부"가 사실은 "한 뉴런 × 수억 번"의 단순 패턴

1750억 개 파라미터를 가진 GPT-3, 700억 개를 가진 Llama, fab의 PatchTST VM 모델 — 모두 본질적으로 같은 한 뉴런의 계산이 다른 모양으로 수억 번 반복된 것입니다. 한 뉴런을 정확히 이해하면 나머지는 "더 많이"의 문제일 뿐입니다.

특히 fab 엔지니어 관점에서 이 한 뉴런 계산을 정확히 보면, "왜 모델 학습이 GPU 없이 안 되는가", "가중치 1억 개가 어떻게 조정되는가", "왜 같은 모델도 데이터에 따라 다른 결과를 내는가" 같은 질문이 자연스럽게 풀립니다.

1.1 시나리오 — "이 wafer가 양품인가?"를 한 뉴런이 판정한다

실제 fab의 단순화된 예시로 시작합니다. 한 wafer를 처리한 후 다음 3가지 측정값이 있다고 합시다:

25.3℃
x₁ — chamber 온도
정상 범위 24~27℃
0.82Pa
x₂ — 진공도
정상 범위 0.7~0.9
120W
x₃ — RF 출력
정상 범위 110~130

질문 — "이 3개 값으로 wafer가 양품인지(1) 불량인지(0)를 추정할 수 있을까?" 한 뉴런이 이 일을 합니다.

1.2 한 뉴런의 4단계 계산

뉴런 1개가 하는 계산은 정확히 4단계입니다:

단계 1 — 가중치 곱셈

각 입력에 "그것의 중요도(가중치)"를 곱한다

이 뉴런이 학습으로 알아낸 가중치가 다음과 같다고 합시다 (학습 후 결정됨):

w₁ = +0.5 ← 온도가 양품 판정에 양의 영향 (높을수록 양품 경향) w₂ = +0.3 ← 진공도도 양의 영향, 단 영향력은 더 약함 w₃ = −0.2 ← RF가 너무 높으면 불량 경향 (음의 영향) 각 입력 × 가중치: x₁·w₁ = 25.3 × 0.5 = 12.65 x₂·w₂ = 0.82 × 0.3 = 0.246 x₃·w₃ = 120 × (−0.2) = −24.0

핵심: "가중치"는 곧 "이 입력을 얼마나 중요하게 볼지"의 숫자입니다. 양수면 "값이 클수록 결과가 커짐", 음수면 "값이 클수록 결과가 작아짐". 학습 = 이 가중치 숫자들을 정답에 맞게 조금씩 조정하는 것.

단계 2 — 합산 + bias

모두 더하고 bias(편향)를 더한다

합산: z = (x₁·w₁) + (x₂·w₂) + (x₃·w₃) + b z = 12.65 + 0.246 + (−24.0) + 9.5 ← b = 9.5 (학습된 bias) z = −1.604

bias (b)는 "기본 편향" — 입력 모두가 0일 때도 뉴런이 어느 정도 활성될지를 결정. 가중치와 함께 학습됩니다. 여기선 b = 9.5가 "기본적으로 양품 쪽으로 편향"을 의미.

단계 3 — 활성 함수 σ

비선형 함수에 통과시킨다 (sigmoid · ReLU 등)

시그모이드 활성: σ(z) = 1 / (1 + e^(−z)) σ(−1.604) = 1 / (1 + e^1.604) = 1 / (1 + 4.97) = 1 / 5.97 = 0.167

활성 함수는 "입력의 합을 0~1 사이의 확률"로 압축합니다. 비선형이라는 것이 핵심 — 이게 없으면 신경망 전체가 그저 큰 1차 함수가 돼버려서 복잡한 패턴을 못 배웁니다. ReLU·tanh·GELU 등 다양한 활성이 있고, 출력층에서 분류는 보통 sigmoid/softmax.

단계 4 — 결과 해석

0~1 출력값을 사람이 읽을 수 있는 답으로

출력 ŷ = 0.167 해석: · ŷ > 0.5 → "양품" (1) · ŷ ≤ 0.5 → "불량" (0) 0.167 < 0.5 이므로 → "이 wafer는 불량 추정" 신뢰도: 1 − 0.167 = 0.833 (83% 불량 확신)

왜 이런 결과가 나왔나? RF 출력이 120W로 다소 높아 음의 가중치(−0.2)와 곱해진 결과(−24.0)가 다른 양의 기여(12.65 + 0.246 + 9.5 = 22.4)를 압도해 z가 음수가 됐고, 시그모이드가 이를 0에 가까운 값으로 변환했기 때문. 가중치의 부호와 크기가 직접적으로 결과를 결정합니다.

1.3 시뮬레이션 — 가중치를 바꾸면 결과가 어떻게 바뀌나

같은 입력 (25.3℃, 0.82Pa, 120W)에 가중치만 다르게 학습된 3개 뉴런이 어떻게 다른 답을 내는지 봅시다:

같은 입력, 다른 가중치 → 다른 결과
가중치가 다르면 완전히 다른 결과가 나옵니다. "학습"이란 곧 "이 가중치 숫자들을 정답에 맞게 조정하는 일"
그림 1.1 — 같은 wafer 입력에 가중치만 바꾸면 결과가 0.167 → 0.999로 완전히 뒤집힘. 모델 = 알고리즘 + 가중치가 왜 별개인지의 직관적 증명.
핵심 직관 — "가중치"는 추상적 개념이 아니라 그냥 숫자입니다. 한 뉴런 안에 +0.5, +0.3, −0.2 같은 숫자가 들어 있고, 입력에 곱해서 합쳐 결과를 만듭니다. 학습 = 이 숫자들이 정답에 맞도록 미세하게 변경되는 일. CNN의 1억 개 가중치도, GPT의 1750억 개 가중치도 모두 이 +0.5, −0.2 같은 작은 숫자들입니다.
INDUSTRY · fab 적용

SK hynix Panoptes의 5천만 개 가중치도 같은 원리

SK hynix Panoptes VM 모델의 약 5천만 개 가중치가 정확히 위와 같은 +0.42, −0.18 같은 숫자들입니다. 챔버 센서 1024개 입력 → 각각 가중치 곱셈 → 합산 → 활성 → 다음 층으로 전달 → 최종 두께 예측. 이 과정이 50개 층 × 1000 뉴런/층 × 1024 입력 = 약 5천만 번의 곱셈이 한 wafer 추론 한 번에 일어납니다.

2

행렬 계산이 뭔지 — 스칼라에서 배치까지 단계별로

"신경망 학습 = 행렬 곱셈"이라고 자주 듣지만, 정확히 무슨 행렬이 어떻게 곱해지는지 헷갈립니다. 한 뉴런부터 시작해 한 층, 한 신경망, 한 배치까지 단계적으로 풀어드립니다.

WHY · 왜 행렬인가

"수백만 번의 같은 패턴 계산"을 한 번에 표현하는 도구

Section 1에서 본 한 뉴런의 계산 — z = w₁x₁ + w₂x₂ + w₃x₃ + b — 은 단순합니다. 그런데 신경망에는 한 층에 1000개 뉴런이 있고, 50개 층이 쌓여있고, 한 번에 32개 wafer를 동시에 처리합니다. 이걸 일일이 for-loop로 쓰면 50 × 1000 × 32 × 1024 = 16억 번의 for-loop가 됩니다.

행렬 곱셈 한 줄(Y = X · W + b)은 같은 16억 개 곱셈을 더 짧게 표현하면서, 동시에 GPU/Tensor Core가 병렬로 동시 실행할 수 있는 형태가 됩니다. 행렬 표기는 단순한 수학 표기 편의가 아니라 하드웨어 효율의 핵심입니다.

2.1 단계 1 — 뉴런 1개 = 벡터 내적

Section 1의 한 뉴런 계산을 행렬 표기로 바꿔봅시다. 입력 3개와 가중치 3개를 벡터로 묶으면:

스칼라 표기 → 벡터 표기

같은 계산을 두 가지 방법으로

기존 (스칼라): z = w₁x₁ + w₂x₂ + w₃x₃ + b z = 0.5×25.3 + 0.3×0.82 + (−0.2)×120 + 9.5 z = −1.604 행렬 표기 (벡터 내적): X = [25.3, 0.82, 120] ← 입력 벡터 (1×3) W = [0.5, 0.3, −0.2] ← 가중치 벡터 (1×3) z = X · Wᵀ + b = [25.3, 0.82, 120] · [0.5, 0.3, −0.2]ᵀ + 9.5 = (25.3)(0.5) + (0.82)(0.3) + (120)(−0.2) + 9.5 = −1.604 ← 정확히 같은 결과!

핵심: 두 표기가 정확히 같은 계산입니다. 단지 행렬 표기는 "여러 곱셈을 한 번에"를 더 자연스럽게 표현할 수 있습니다. 벡터 내적(또는 dot product)이 모든 신경망의 가장 작은 단위 연산입니다.

2.2 단계 2 — 한 층 = 행렬 곱셈

이제 같은 입력 3개를 받아 4개 뉴런이 동시에 계산한다고 합시다. 각 뉴런은 자신만의 가중치 3개를 가집니다 — 즉 가중치가 4×3 = 12개:

한 층의 4개 뉴런 동시 계산

같은 입력에서 4개 다른 hidden feature를 추출

입력 X (1×3): X = [25.3, 0.82, 120] 가중치 W (3×4 — 입력 3개 × 뉴런 4개): 뉴런1 뉴런2 뉴런3 뉴런4 W = [ 0.5 0.1 −0.3 0.2 ] ← 입력 x₁(온도)과 곱해질 가중치 [ 0.3 2.0 0.1 0.4 ] ← 입력 x₂(진공도) [−0.2 −0.1 −0.5 −0.3 ] ← 입력 x₃(RF) bias b (1×4): b = [9.5, −5.0, 60.0, 32.0] 행렬 곱 Z = X · W + b: Z₁ = 25.3×0.5 + 0.82×0.3 + 120×(−0.2) + 9.5 = −1.604 Z₂ = 25.3×0.1 + 0.82×2.0 + 120×(−0.1) + (−5.0) = −10.83 Z₃ = 25.3×(−0.3) + 0.82×0.1 + 120×(−0.5) + 60.0 = −7.428 Z₄ = 25.3×0.2 + 0.82×0.4 + 120×(−0.3) + 32.0 = 1.388 Z = [−1.604, −10.83, −7.428, 1.388] ← 4개 뉴런의 출력 H = σ(Z) = [0.167, 0.00002, 0.00059, 0.800] ← 활성 함수 통과

핵심 관찰: 같은 입력 [25.3, 0.82, 120]이 4개 뉴런을 통과해 4가지 다른 의미의 hidden 값이 됐습니다. 각 뉴런은 다른 가중치를 가졌으니 다른 패턴(예: "양품 가능성", "온도 비정상", "RF 과다", "복합 조건 통과")을 학습했다고 볼 수 있습니다. 이게 신경망의 "특징 추출"의 본질입니다.

2.3 단계 3 — 깊은 신경망 = 여러 층의 행렬 곱셈

이제 4개 hidden 출력을 다음 층의 입력으로 보냅니다. 다음 층이 1개 출력을 갖는다면:

2-layer 신경망 = 행렬 곱 2번

입력 → hidden(4) → 출력(1)

Layer 1: X(1×3) · W₁(3×4) + b₁(1×4) → H(1×4) [25.3, 0.82, 120] · [3×4 행렬] + [4-벡터] → [0.167, 0.00002, 0.00059, 0.800] Layer 2: H(1×4) · W₂(4×1) + b₂(1×1) → ŷ(1×1) [0.167, 0.00002, 0.00059, 0.800] · [4×1 행렬] + 스칼라 → 스칼라 결과 수식으로 한 줄: ŷ = σ(σ(X · W₁ + b₁) · W₂ + b₂) 학습 대상 가중치: W₁ (12개) + b₁ (4개) + W₂ (4개) + b₂ (1개) = 21개

핵심: 깊은 신경망이라도 "행렬 곱 + 활성"의 반복일 뿐입니다. GPT의 1750억 가중치도 똑같은 패턴이 더 많이 쌓인 것 — 한 줄 식으로 표현하면 ŷ = f_50(... f_2(f_1(X)))의 50번 합성 함수.

2.4 단계 4 — 배치 처리 = 행렬 × 행렬

지금까지는 한 번에 wafer 1장을 처리했습니다. 실제로는 32장이나 256장의 wafer를 동시에 처리합니다 (이를 "batch"라 함). 이때 입력이 행렬이 됩니다:

batch 32장 동시 처리

왜 GPU가 좋아하는 형태가 되는가

한 wafer (앞에서 본 것): X (1×3) · W (3×4) → H (1×4) batch 32 wafer 동시: X (32×3) · W (3×4) → H (32×4) X = [ [25.3, 0.82, 120], ← wafer 1 [25.5, 0.85, 118], ← wafer 2 [24.9, 0.81, 122], ← wafer 3 ... ← 29개 더 [25.4, 0.83, 119] ← wafer 32 ] 같은 W (3×4)와 곱하면 → 32개 wafer 결과를 동시에 얻음. 곱셈 횟수 = 32 × 3 × 4 = 384개 ← 모두 독립적, 병렬화 가능! 이게 GPU의 매력 (Section 4 참조)

핵심 관찰: 32개 wafer의 384번 곱셈은 서로 의존성이 없습니다 — wafer 1의 계산이 wafer 2의 계산에 영향을 주지 않음. 따라서 384개를 동시에 실행 가능. GPU의 수천 코어가 이걸 한 번에 처리 → CPU 대비 1000배 가속의 비밀 (Section 4).

2.5 행렬 크기 한 눈에 보기

스칼라 → 벡터 → 행렬 → 텐서 — 데이터 차원의 진화
그림 2.1 — 데이터의 차원 진화. fab의 PatchTST 입력은 보통 4D 텐서: (32 batch, 96 timestep, 32 sensor, 1 channel) = 약 10만 개 숫자 한 묶음.
핵심 직관 — 모든 신경망 계산은 결국 "숫자 표 × 숫자 표"의 반복. 행렬 곱셈은 새로운 수학이 아니라 단지 "같은 곱셈 패턴을 한 번에 수억 개 표현하는 표기법"입니다. 그리고 이 표기법이 GPU와 만났을 때 진가를 발휘합니다 (다음 섹션).
3

가중치는 어떻게 학습되나 — 50만 회 반복으로 일어나는 일

Section 1에서 본 가중치 +0.5, +0.3, −0.2는 어디서 왔을까요? "학습 데이터로 자동 조정"이라는 한 마디 뒤에 무엇이 일어나는지 끝까지 따라갑니다.

3.1 학습 시작 — 가중치가 처음에는 무작위

모델을 처음 만들 때, 모든 가중치는 무작위 작은 숫자로 초기화됩니다 (대부분 −0.1 ~ +0.1 사이의 정규분포 무작위). 이 시점의 모델은 아무 것도 모르는 상태 — 입력을 줘도 의미 없는 출력을 냅니다.

학습 0회 (초기화)

아직 아무 것도 모르는 모델

초기 무작위 가중치: W = [0.043, −0.087, 0.012] ← 무작위 b = 0.005 입력: [25.3, 0.82, 120] (실제 정답은 "양품" = 1) z = 25.3×0.043 + 0.82×(−0.087) + 120×0.012 + 0.005 = 1.088 − 0.071 + 1.440 + 0.005 = 2.462 ŷ = σ(2.462) = 0.921 ← 우연히 양품 예측 (운 좋음) 손실 (정답 1과의 차이): Loss = (1 − 0.921)² = 0.0062 ← 작은 손실

이 케이스는 운 좋게 정답을 맞춘 것 — 무작위 가중치는 절반 정도는 틀립니다. 학습은 이런 손실을 0으로 줄여나가는 과정입니다.

3.2 학습 1회 — 정답과의 차이로 가중치를 조정

모델이 "불량"을 "양품"으로 잘못 예측한 경우를 봅시다:

학습 한 번의 실제 흐름

예측이 틀렸을 때 가중치를 어떻게 조정하나

현재 가중치: W = [0.043, −0.087, 0.012], b = 0.005 입력: [22.1, 0.78, 145] (정답: 불량 = 0) Step 1: forward (예측 시도) z = 22.1×0.043 + 0.78×(−0.087) + 145×0.012 + 0.005 = 2.640 ŷ = σ(2.640) = 0.933 ← "양품"으로 잘못 예측! Step 2: 손실 계산 Loss = (0 − 0.933)² = 0.871 ← 큰 손실 (정답에서 멀리 벗어남) Step 3: backward (각 가중치의 기울기 계산) ∂L/∂w₁ = 2 × (0.933 − 0) × σ'(2.640) × 22.1 = +2.566 ∂L/∂w₂ = 2 × (0.933 − 0) × σ'(2.640) × 0.78 = +0.091 ∂L/∂w₃ = 2 × (0.933 − 0) × σ'(2.640) × 145 = +16.84 ∂L/∂b = 2 × (0.933 − 0) × σ'(2.640) = +0.116 Step 4: update (학습률 η = 0.001만큼 반대 방향으로) w₁ ← 0.043 − 0.001 × 2.566 = 0.0405 (소폭 감소) w₂ ← −0.087 − 0.001 × 0.091 = −0.0871 (거의 그대로) w₃ ← 0.012 − 0.001 × 16.84 = −0.0048 (음수로 전환!) b ← 0.005 − 0.001 × 0.116 = 0.0049

핵심 관찰: RF 출력(x₃=145, 정상보다 높음)이 양품 예측을 만들어낸 주범이라 그 가중치 w₃가 가장 크게 조정됩니다(0.012 → −0.0048, 음수로 전환). 이제 이 모델은 "RF 높은 입력은 불량 쪽으로 기울어지는" 약간의 학습을 한 것. 한 번에 작은 변화지만, 이걸 50만 번 반복하면 모델이 점점 똑똑해집니다.

3.3 학습 50만 회 — 가중치가 의미 있는 값으로 수렴

학습 진행에 따른 손실 + 가중치 변화 (실제 시뮬레이션)
그림 3.1 — 학습 50만 회의 실제 모습. 손실은 0.87 → 0.01로 감소. 가중치는 무작위 0 근처에서 의미 있는 값(+0.5, +0.3, −0.2)으로 수렴.
학습이란 무엇인가 — Section 1의 가중치 (+0.5, +0.3, −0.2)는 50만 번의 작은 조정 결과입니다. 한 번 조정의 크기는 0.001 단위로 작지만, 50만 번 반복되면 가중치가 무작위에서 의미 있는 값으로 수렴합니다. 이게 "학습"이라는 말의 실제 의미.

GPU가 왜 필수인가 — CPU와의 1만 배 차이

Section 2에서 본 행렬 곱셈은 "독립적인 곱셈의 묶음"입니다. 이 특성이 GPU와 결합할 때 발생하는 1만 배 가속의 비밀을 끝까지 풀어드립니다.

WHY · 왜 CPU로는 안 되는가

"50만 회 학습 × 5천만 곱셈/회 = 25조 곱셈"이라는 현실

Section 3의 SK hynix Panoptes 학습 한 번에 25조 회의 곱셈이 일어납니다. 일반 CPU(예: Intel Core i9, 24 코어, 5GHz, 코어당 한 번에 1개 곱셈)로 이걸 처리하면 — 약 250일이 걸립니다.

GPU(예: NVIDIA H100, 16,896 CUDA 코어 + 528 Tensor Core)로는 같은 작업이 약 3일에 끝납니다. 약 80배 가속(실제로는 메모리·통신 등 오버헤드로 단순 코어 수 비례보다는 약간 적음). Tensor Core 같은 특수 유닛까지 활용하면 1000배 이상 가속도 가능합니다.

이 차이가 단순한 "더 빠름"이 아닙니다 — "가능 vs 불가능"의 차이입니다. 매주 새 모델을 학습해 fab에 배포하려면 학습 시간이 일주일 안이어야 하는데, CPU로는 절대 불가능. GPU 없으면 현대 fab AI는 존재하지 않습니다.

4.1 CPU와 GPU의 근본적 차이

같은 반도체로 만들지만 설계 철학이 정반대입니다:

🖥️ CPU — "소수의 똑똑한 일꾼"

복잡하고 다양한 작업을 빠르게 처리하도록 설계. 다양한 분기·점프·캐시 관리를 지능적으로 처리.

  • 코어 수: 4~64 (소비자) / 64~256 (서버)
  • 코어 1개의 능력: 매우 강력 (5GHz · 분기 예측 · OoO 실행)
  • 한 번에 처리: 24 코어 = 24가지 다른 작업 동시
  • 강점: 운영체제, 데이터베이스, 일반 코드, 분기 많은 작업
  • 약점: 같은 작업을 수만 번 하는 데는 비효율

🎮 GPU — "수만 명의 단순 일꾼"

같은 단순 연산을 동시에 수만 개 처리하도록 설계. 단순한 코어를 어마어마하게 많이 박은 것.

  • 코어 수: 10,000~17,000 (NVIDIA H100 = 16,896 CUDA + 528 Tensor)
  • 코어 1개의 능력: 단순함 (1.4GHz · 분기 약함)
  • 한 번에 처리: 16,896 코어 = 같은 패턴 16,896번 동시
  • 강점: 행렬 곱, 픽셀 처리, 같은 패턴 대량 반복
  • 약점: 분기·복잡 로직·운영체제는 못 함
CPU vs GPU — 행렬 곱셈 한 번에 어떻게 다른가
그림 4.1 — 100만 회의 곱셈을 처리할 때 CPU 24코어와 GPU 16,896코어의 차이. 행렬 곱셈은 모든 곱이 독립적이라 GPU 병렬화에 완벽히 맞아떨어짐.

4.2 왜 행렬 곱셈이 GPU에 완벽한가

GPU가 신경망에서 압도적으로 빠른 이유는 단순합니다 — 행렬 곱셈의 모든 단일 곱셈이 독립적이기 때문:

왜 병렬화가 가능한가

X (32×3) · W (3×4) = Y (32×4) 의 32×4 = 128개 결과는 모두 독립

예시: 결과 행렬 Y의 [0,0]번 원소를 계산하려면: Y[0,0] = X[0,0]×W[0,0] + X[0,1]×W[1,0] + X[0,2]×W[2,0] ← 3번 곱셈 같은 시간에 다른 코어가 Y[0,1]을 계산: Y[0,1] = X[0,0]×W[0,1] + X[0,1]×W[1,1] + X[0,2]×W[2,1] ← 다른 3번 곱셈 또 다른 코어가 Y[0,2]: Y[0,2] = X[0,0]×W[0,2] + X[0,1]×W[1,2] + X[0,2]×W[2,2] ... 128개 결과를 동시에 (병렬로) 계산 가능 ↓ GPU 코어 128개가 한 번에 처리 → 단일 사이클에 끝남 CPU 24코어는 24개씩 → 6번 사이클 필요 GPU 16,896코어는 128개 모두 동시 → 1번 사이클

4.3 Tensor Core — 신경망 전용 가속

2017년부터 NVIDIA는 Tensor Core라는 "행렬 곱셈 전용 회로"를 GPU에 추가했습니다. 일반 CUDA 코어가 한 번에 1개 곱셈을 한다면, Tensor Core는 한 번에 4×4 행렬 곱셈 (= 64개 곱셈)을 한 사이클에 처리합니다:

1회/cycle
CPU 코어 한 개
단일 곱셈
1회/cycle
CUDA 코어 한 개
단일 곱셈 × 16,896개 동시
64회/cycle
Tensor Core 한 개
4×4 행렬 곱셈 한 번에
33,792회/cycle
H100 전체 (528개 TC)
528 TC × 64 = 한 사이클 33,792 곱셈

간단 계산으로 H100 GPU 한 대가 한 사이클에 33,792 곱셈, 클럭 1.7 GHz × 33,792 ≈ 초당 57조 곱셈 정도가 나옵니다. 실제 NVIDIA 공식 datasheet 기준 H100의 FP16 Tensor Core 성능은 약 989 TFLOPS(비-sparse), FP8에서는 약 1,979 TFLOPS로 위 단순 계산보다 훨씬 큽니다(FMA 카운트 · 다중 연산 파이프라인 · sparsity 등 추가 가속이 반영됨). CPU 한 대(24코어급)가 약 1~2 TFLOPS 수준이니, 같은 행렬 곱셈 작업에서 GPU가 CPU 대비 수백~천 배 빠름이 핵심 결론입니다.

이 모든 작업의 사업적 가치 — variability −29%

SK hynix Newsroom 공개 — Panoptes VM 도입 후 증착 공정 variability가 29% 감소. 이는 wafer당 평균 ±0.5nm 더 정확한 두께 제어를 의미하고, 곧 수율 +0.5%p 정도의 효과 (구체 수치 비공개). 분기 매출 수십~수백억 단위의 가치가, 이 자료에서 본 가중치·행렬·GPU의 작동 메커니즘 위에서 만들어집니다.

★ 5섹션 통합 — 신경망 완전 정복 요약

지금까지 본 5개 섹션을 한 줄씩 정리. 이 5문장이 머리에 들어 있으면 CNN · Transformer · LLM 모든 자료가 자연스럽게 풀립니다.

SECTION 1
한 뉴런 = 곱셈 + 합 + 활성. 가중치는 그냥 +0.5, −0.2 같은 작은 숫자.
"학습"이란 이 가중치 숫자가 정답에 맞도록 미세하게 변경되는 일. 같은 모델이라도 가중치가 다르면 완전히 다른 결과를 냄.
SECTION 2
행렬 곱셈은 "같은 패턴의 곱셈을 한 번에 수억 개 표현하는 표기법".
스칼라 → 벡터 (한 wafer) → 행렬 (batch wafer) → 텐서 (시계열 batch wafer)로 차원이 자유롭게 확장됨. 배치 처리 덕분에 GPU 병렬화가 가능해짐.
SECTION 3
학습 = 50만 번의 작은 가중치 조정. 한 번 조정은 0.001 단위.
손실의 기울기를 따라 가중치가 무작위에서 의미 있는 값으로 수렴. 이게 신경망이 "데이터로부터 학습"하는 정확한 메커니즘.
SECTION 4
GPU = 16,896 단순 코어 × Tensor Core. 행렬 곱셈에 완벽히 맞아떨어짐.
CPU 250일 학습이 GPU 3일로. 매주 모델 갱신이 필요한 fab AI는 GPU 없이는 절대 불가능. NVIDIA가 fab AI 시대의 인프라 독점.
SECTION 5
SK hynix Panoptes VM = 5천만 가중치 × 50만 학습 × 매주 갱신.
3,072 센서 숫자 → 5단계 행렬 변환 → 두께 1 숫자 (0.4ms/wafer). 이 작동이 수율 −29% variability라는 사업적 가치로 변환됨.
마지막 한 줄 — CNN의 1억 가중치, Transformer의 1750억 가중치, LLM의 671B 가중치 — 이 모든 거대 숫자가 사실은 "+0.5, −0.2 같은 작은 숫자가 더 많이 있는 것"일 뿐. 한 뉴런의 단순한 곱셈·합·활성 패턴이 GPU 위에서 수억 번 반복되며 만들어지는 것이 현대 AI의 모든 것.
