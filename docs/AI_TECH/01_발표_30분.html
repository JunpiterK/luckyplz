PART A · 기초 03 / 18 먼저 이것부터

5개 핵심 용어를 한 장으로

이 다섯 단어를 정확히 구분하면 나머지 모든 슬라이드가 훨씬 잘 읽힙니다. 특히 알고리즘과 모델의 차이는 자주 혼동되니 짚고 시작합니다.

FAB 팹 — 양산 라인

Fabrication Facility의 줄임말. 반도체 칩이나 디스플레이 패널을 대량 생산하는 공장.

레시피 책으로 빵을 굽는 공장 — 똑같은 결과를 수만 번 반복해야 한다.

SK hynix 이천 M16 / 삼성 평택 P3 / TSMC Hsinchu Fab 18

AI 인공지능

Artificial Intelligence. 컴퓨터가 데이터에서 패턴을 발견하고 그 패턴으로 새 입력에 답을 내는 능력의 총칭.

사람이 경험으로 "이건 불량 같다"고 직감하는 것을, 컴퓨터가 데이터로 흉내내는 것.

결함 사진 → "scratch" 라벨 자동 분류

ML 기계학습

Machine Learning. AI를 구현하는 주류 방법. "규칙을 사람이 직접 코딩하지 않고, 데이터에서 자동으로 학습한다"가 핵심.

요리책 레시피를 외우는 게 아니라, 손님 평을 보고 양념 비율을 스스로 조정하는 셰프.

결함 1만 장으로 분류 모델 자가 학습

알고리즘 Algorithm

문제를 푸는 방법·절차의 청사진. CNN · Transformer · Q-learning 같은 이름이 모두 알고리즘. 코드를 짜기 전의 "설계도"에 해당.

"빵을 만드는 방법" 그 자체. 재료(데이터) 없이 방법만 있는 상태.

CNN 알고리즘 → 이미지에서 패턴을 찾는 절차

모델 Model

알고리즘이 특정 데이터로 학습을 마친 결과물. 알고리즘은 청사진이고, 모델은 그 청사진으로 데이터를 학습해 만들어진 "완성품".

레시피(알고리즘)를 따라 실제로 구운 빵(모델). 같은 레시피라도 재료가 다르면 다른 빵이 나온다.

CNN 알고리즘으로 SK hynix 결함 이미지를 학습 → SK hynix 전용 결함 분류 모델

핵심 알고리즘은 "방법", 모델은 "방법을 데이터로 적용해서 만든 결과물". 같은 알고리즘(CNN)도 SK hynix와 TSMC가 학습하면 서로 다른 모델이 됩니다.
PART A · 기초 04 / 18 팹은 무엇을 만드는 곳인가

반도체 팹 vs 디스플레이 팹 — 한 장으로

AI 적용 사례를 이해하려면 두 종류 팹의 핵심 차이만 알면 됩니다. 데이터 종류와 검사 방식이 약간 다를 뿐 운영 개념은 거의 같습니다.

PART A · 기초 05 / 18 데이터가 있어야 AI가 산다

팹에서 나오는 데이터 6가지

AI 모델은 데이터로 학습합니다. 어떤 데이터가 어디서 얼마나 나오는지가 곧 어떤 AI가 가능한지를 결정합니다.

📈1. FDC 시계열

FDCFault Detection & Classification, 결함 탐지·분류
장비 센서 수천 개가 1-100Hz로 만드는 다변량 시계열. 예: chamber 온도, RF power, gas flow

하루 10-50 TB · 라벨 0%

📏2. Inline Metrology

인라인 계측 — 두께, CDCritical Dimension, 임계 치수, overlay 같은 wafer 출력값을 라인 안에서 직접 측정. 통상 5-25 wafer 당 1회.

VM 모델의 정답 라벨이 됨

🔬3. AOI / SEM 이미지

AOIAutomated Optical Inspection, 자동 광학 검사 광학 이미지 + SEMScanning Electron Microscope, 주사 전자 현미경 전자 현미경 이미지. 결함을 찾고 분류하는 핵심 자료.

CNN ADC의 입력

📋4. MES 운영 이력

MESManufacturing Execution System, 제조 실행 시스템 — 어느 lot이 어느 chamber에서 어느 recipe로 언제 처리됐는지의 시간 이력.

GNN/그래프 분석의 기반

📄5. 사내 문서

SOPStandard Operating Procedure, 표준 작업 절차 · ECNEngineering Change Notice, 설계 변경 통지 · 8DEight Disciplines, 8단계 문제 해결 보고서. 자연어 / PPT / Excel 형식.

LLM/RAG 코파일럿의 코퍼스

⚙️6. 장비 건강 신호

장비별 진동, 압력, 온도 같은 보조 센서. PdMPredictive Maintenance, 예지 보전과 OEE 관리에 사용.

Anomaly Detection 1순위
현실 데이터는 매일 수십 TB 쏟아지지만 라벨이 붙은 비율은 0.01% 미만. 이 문제 자체가 fab AI의 절반 이상을 결정합니다 — DINOv2 같은 자기지도 학습이 부각된 이유.
PART A · 기초 06 / 18 AI는 무엇을 하는가

AI가 푸는 3가지 문제 — 분류 · 회귀 · 행동

팹에서 마주치는 거의 모든 AI 문제는 이 셋 중 하나입니다. 어떤 유형인지를 먼저 파악하면 적합한 알고리즘이 자연히 좁혀집니다.

🏷️① 분류 (Classification)

"이게 무엇인가?"
입력을 미리 정해진 카테고리 중 하나로 배정.

팹 예시 — ADC자동 결함 분류: 결함 사진 → "scratch / particle / short …" 중 하나

대표 알고리즘 → CNN · ViT · LLM 분류

📐② 회귀 (Regression)

"얼마나?"
입력으로부터 연속적인 숫자를 예측.

팹 예시 — VM가상 계측: 센서 시계열 → 두께 8.7 nm 예측

대표 알고리즘 → PatchTST · iTransformer · LSTM · GBT

🎮③ 행동 (RL)

"어떻게 할까?"
현재 상태를 보고 다음 행동을 선택. 보상으로 학습.

팹 예시 — APC고도 공정 제어: 챔버 상태 → "온도 +0.5℃ 조정"

대표 알고리즘 → DQN · PPO · CQL · DreamerV3
참고 4번째 유형으로 생성(Generation)이 있습니다 — Diffusion으로 결함 이미지 합성, LLM으로 8D 보고서 작성 등. 슬라이드 8에서 다룹니다.
PART B · AI 알고리즘 07 / 18 신경망 — 모든 딥러닝의 기초

신경망은 결국 "숫자 곱하기 + 덧셈 + 비선형"의 반복

CNN · Transformer · LLM 모두 이 단순한 연산을 수억 번 반복하는 구조입니다. 학습이란 곧 곱할 가중치 (weight)를 데이터로 조정하는 일입니다.

비유 요리사가 손님 평을 보고 다음번엔 소금을 0.42g 더 넣고 후추는 0.18g 빼는 식으로 레시피(가중치)를 미세 조정하는 것 — 이게 바로 신경망 학습입니다.
PART B · AI 알고리즘 08 / 18 알고리즘 분류

팹에 쓰이는 8개 알고리즘 가족

같은 신경망 구조를 어떤 데이터·문제에 맞췄느냐에 따라 다른 가족이 됩니다. 16개 사례 모두 이 8개 안에서 변형됩니다.

①

CNN — 합성곱

이미지의 공간 패턴을 찾는 도구. 같은 작은 필터를 슬라이딩하며 특징 추출.

원조 ResNet (2015) → DINOv2 (2023)

②

Transformer

모든 토큰이 모든 토큰을 어텐션으로 본다. 언어 + 비전 + 시계열 통합.

원조 Attention (2017) → ViT · Swin

③

시계열 모델

시간 흐름의 미래값 예측. VM의 핵심.

원조 LSTM (1997) → PatchTST (2023) · TimesFM (2024)

④

Tabular ML

표 형태 데이터(센서값 + 카테고리)에서 수율·고장 예측.

원조 XGBoost (2016) → SHAP · TabPFN

⑤

GNN — 그래프 학습

노드(chamber/lot)와 엣지(흐름)로 이루어진 그래프에서 패턴 학습.

원조 GCN (2017) → HGT (2020)

⑥

강화학습 (RL)

시행착오로 행동 정책 학습. 양산은 Offline RL이 안전 경로.

원조 DQN (2015) → CQL · DreamerV3

⑦

Diffusion 생성

노이즈 → 이미지로 단계적 복원. 결함 합성·EUV 추계 모델링에 사용.

원조 DDPM (2020) → ControlNet · FLUX

⑧

LLM — 대규모 언어 모델

자연어로 사내 자료 검색·요약·작성. RAG로 환각 방지.

원조 GPT-3 (2020) → DeepSeek-R1 · Claude 3.7

읽는 법 ①~④는 "패턴 인식·예측" — 데이터를 받아 답을 낸다. ⑤~⑥은 "구조·행동" — 관계나 의사결정. ⑦~⑧은 "생성" — 새로운 데이터를 만든다.
PART B · AI 알고리즘 09 / 18 학술 → 양산

원본 알고리즘이 산업으로 들어올 때 3가지 변형이 따라온다

학술 논문의 알고리즘을 양산 라인에 그대로 쓰는 회사는 없습니다. 이 세 가지 변형이 거의 모든 사례에서 반복됩니다.

① 도메인 적응 (Backbone 동결)

사전학습된 일반 모델(ResNet · DINOv2)의 대부분을 동결하고 마지막 layer만 fab 데이터로 미세조정.

왜? 라벨이 적은 fab 데이터로도 성능을 살리기 위해. 1만 장 라벨이 100장으로 줄어드는 효과.

사례: Intel ADC · Applied ExtractAI · KLA Multi-Perspective

② 불확실성 정량화

단일 점 예측이 아닌 예측값 + 신뢰구간을 동시에 출력. Bayesian Last Layer · Deep Ensemble · Heteroscedastic loss 셋 중 하나가 표준.

왜? APC가 "이 예측을 믿어도 되는지"를 판단해야 함. 잘못된 자신감은 lot 손실로 직결.

사례: SK hynix Panoptes (Bayesian LL) · Gauss Labs SPIE 2024 발표

③ 안전 제약 + 섀도우 배포

학습된 정책이 recipe 안전 범위를 절대 넘지 못하게 hard constraint. 처음엔 추천만 출력하는 섀도우 모드로 배포 후 단계적 승격.

왜? 양산 라인은 PoC가 아님. 한 번의 실수가 lot 손실 · 신뢰 상실로 이어짐.

사례: LG Display Mura RL · Intel n-i to n APC · 모든 RL 사례

핵심 "최신 SOTA 모델 = 양산 적합 모델"이 아닙니다. 정확도 1%를 더 얻는 것보다 uncertainty가 정직하고 안전 제약이 들어간 모델이 양산에 들어갑니다.
PART B · AI 알고리즘 10 / 18 사례 횡단 패턴

16건 사례에서 반복되는 5가지 패턴

회사·국가·공정이 다른데도 같은 메커니즘이 반복됩니다. 사례를 읽을 때 이 5개 렌즈로 보면 빠르게 패턴이 잡힙니다.

PATTERN 1

섀도우 배포 → 점진 승격이 양산 진입의 표준

SK hynix Panoptes · Intel n-i to n · LG Display Mura RL — 모두 처음에는 추천만 출력하는 섀도우 모드로 시작.

PATTERN 2

사전학습 백본 + Last-Layer 미세조정 = 사실상 표준

DINOv2 · ResNet 백본을 동결하고 도메인별 head만 학습. Intel · Applied · KLA가 같은 패턴.

PATTERN 3

불확실성 정량화 없는 VM은 APC에 못 쓴다

Bayesian Last-Layer · Heteroscedastic loss · Deep Ensemble 셋 중 하나는 필수.

PATTERN 4

LLM은 RAG + 온프렘 + 사인오프가 양산 골격

Micron · BOE · CSOT · Samsung Display 모두 동일 — IP 보안과 환각 방지를 위해.

PATTERN 5

CNN이 아직도 fab AI의 진입점

16건 중 13건이 CNN을 핵심 또는 보조로 사용. 검사가 가장 빠른 ROI를 만든다.

KRSK hynix × Gauss Labs Panoptes VMTier A

측정하지 않은 wafer의 두께를 센서 데이터만으로 추정하는 가상 계측 모델. 한국 메모리 fab의 AI 적용 사례 중 가장 정량적으로 공개된 사례.

왜 풀어야 했나

증착(CVD/PVD) 같은 공정은 nm 단위 두께가 수율을 좌우. 하지만 인라인 메트롤로지는 5-25 wafer 당 1회밖에 측정 못 함. 그 사이 처리되는 wafer는 "옛날 측정값"으로 제어됨 — 이를 샘플링 갭 (Sampling Gap)이라 부름.

적용 알고리즘

베이스라인
LSTM 단일 회귀, 점 추정만, uncertainty 없음.
→
적용
Transformer encoder + Bayesian Last Layer
+ tool 공통 trunk + chamber별 head
+ PM-aware sequence token

3가지 산업 변형이 모두 들어감 — ① 도메인 적응 (chamber별 head), ② 불확실성 정량화 (Bayesian LL), ③ 안전 제약 (섀도우 배포 후 승격).

결과 KPI

  • 증착 공정 variability −29% (SK hynix Newsroom)
  • 누적 가상계측 wafer 5,000만+ (2022.12~)
  • SPIE AL 2024 · 2026 공동 논문 2건
  • 2024.08 Etch 영역으로 Panoptes VM 2.0 확장

이 사례가 보여주는 것

  • 샘플링 갭은 AI로 메울 수 있다 — 기존 측정 없이도 wafer-level 추정 가능
  • 섀도우 배포가 양산 진입의 표준 경로 — 처음에는 APC와 병행만, 검증 후 주 입력으로 승격
  • Tool 공통 trunk + chamber별 head 구조가 신규 챔버 학습을 일주일 단위로 가능하게 함
참고 Panoptes는 외부 회사 Gauss Labs와의 협업 결과로, SK hynix가 투자사. SPIE Advanced Lithography 학회에서 공동 논문 발표.
PART C · 사례 deep dive 13 / 18 사례 2 · 검사 자동화의 누적

USIntel n-i to n APC 13년 누적Tier B

한 번에 큰 모델을 들이지 않고 13년에 걸쳐 한 도메인씩 정복한 누적 전략. fab AI 거버넌스의 교과서.

"n-i to n" APC가 무엇인가

전통 R2RRun-to-Run, 공정 간 피드백는 n-1 lot의 측정으로 n+1 lot을 보정. 시간차로 lot 손실 발생.

Intel n-i to n은 n-2, n-3 lot 데이터까지 ML로 통합해 n lot에 즉시 보정 적용. Intel 공식: "Data from n-i steps is used to control the process at step n through machine learning."

7개 축 ML 프로그램 (2018-2024 누적)

  1. CNN ADC — SEM 결함 자동 분류 (2018)
  2. Generative FA (GFA) — wafer map long-tail 결함 합성 (2020)
  3. n-i to n APC ML — 위 도식 (2021)
  4. Equipment Health — 시계열 anomaly (2022)
  5. Recipe BO — 신규 recipe 자동 탐색 (2023)
  6. Lot Dispatching RL — 우선순위 결정 (2023)
  7. LLM Co-pilot — SOP/ECN 검색 (2024)
  • 2018-2023 누적 절감 $1B+ (Intel IR)
  • ADC 처리량 3-7×
  • R2R 변동성 20-40% 감소
이 사례의 메시지 "AI 한 방"이 아니라 13년에 걸쳐 16개 모델이 함께 돈다는 규모감이 진짜 자산. 모든 사례에 적용되는 MLOps + Feature Store 기반이 핵심.
PART C · 사례 deep dive 14 / 18 사례 3 · 그래프로 수율을 푼다

TWTSMC HGT 기반 수율 RCATier B

한 lot이 1500+ step을 거치며 수십 개 chamber를 통과. 어느 chamber의 어느 step이 수율 저하를 일으켰는지를 그래프 신경망으로 학습.

왜 그래프인가

전통 SHAP-on-XGBoost는 "feature 간 상관"은 잡지만 "lot이 어느 chamber 그래프를 통과했나"는 못 잡음.

HGTHeterogeneous Graph Transformer는 노드 타입별로 attention head를 분리. chamber·recipe·lot이 같은 그래프 안에서 서로 다른 의미로 다뤄짐.

적용 알고리즘

베이스라인
XGBoost + SHAP. chamber·tool을 단순 one-hot 변수로 처리.
→
적용
HGT (Heterogeneous Graph Transformer)
+ Time-aware edge timestamp
+ Yield label as supervised target
+ Attention weight 시각화

결과

  • 3nm 양산 첫 분기 yield ramp 이전 노드 대비 30%+ 가속 (TSMC 2024 IR Day)
  • RCA 시간 일 단위 → 시간 단위 (IEDM 2023)
  • 2022 IEDM 첫 발표 → 2023 IEDM 후속 → Hsinchu Fab 18 양산 적용

이 사례가 보여주는 것

  • fab은 본질적으로 그래프 — 1500 step이 수십 chamber를 거침. 이 구조 자체를 모델에 입력하면 RCA 정확도가 자릿수 차이로 향상
  • 학회 발표 의무가 TSMC AI의 비밀 — 사내 기술이 외부 검증을 받아야 진짜 자산

  • B8 단품 검사 20s → 2.5s
  • Miss-rate 8% → 0.3%
  • 연 2억 RMB+ 절감 (B8 한정)

PART C · 사례 deep dive 16 / 18 사례 5 · GPU로 EUV를 가속

USTWEUNVIDIA cuLitho × TSMC · Samsung · ASMLTier A

EUVExtreme Ultraviolet, 극자외선 마스크 보정에 들던 시간을 2주 → 8시간으로 압축. 7nm 이하 양산을 가능하게 한 인프라 기술.

OPC가 무엇인가

OPCOptical Proximity Correction, 광학 근접 보정는 마스크 패턴이 wafer에 그대로 그려지지 않는 광학적 왜곡을 미리 보정하는 시뮬레이션. 한 번 돌리는 데 CPU 수만 코어 × 2주 필요.

cuLitho의 3가지 변형

① GPU 라이브러리화

lithography 시뮬레이션의 핵심 연산(Hopkins integral, FFT)을 CUDA로 재구현. 500 CPU = 1 H100 GPU.

② ML-Augmented OPC

CNN으로 OPC 결과를 직접 예측하는 보조 모델. 시뮬레이션 결과를 학습 데이터로 활용.

③ EUV Stochastic Modeling

photoresist의 photon shot noise를 score-based generative model로 학습 (Diffusion 원리). ASML 협업.

  • OPC 처리 시간 2주 → 8시간 (NVIDIA GTC 2024)
  • 전력 소비 ~10% 수준 (수만 CPU vs 수백 GPU)
  • 2nm 노드 마스크 보정의 경제적 실용화
참고 2023년 GTC 첫 발표(TSMC, Samsung, ASML, Synopsys 동시 참여) → 2024년 GTC 양산 도입 발표. 1년 만에 산업 표준 진입.

PART D · 정리 18 / 18 마무리

핵심 메시지 — 5줄 요약

① 알고리즘과 모델은 다르다. 알고리즘은 "방법(레시피)", 모델은 "데이터로 학습된 결과물(빵)". 같은 CNN 알고리즘도 SK hynix와 TSMC가 학습하면 서로 다른 모델이 된다.
② VM + APC가 양산 적용의 가장 측정 가능한 앵커다. SK hynix Panoptes의 variability −29%가 한국 메모리 fab의 대표 사례. Transformer 시계열 + Bayesian Last Layer 조합이 핵심 변형.
③ 학술 모델은 그대로 양산에 안 들어간다. ① 도메인 적응 (Backbone 동결) · ② 불확실성 정량화 · ③ 안전 제약 + 섀도우 배포 — 이 3가지 변형이 거의 모든 사례에서 반복된다.
④ LLM은 오케스트레이터, 대체재가 아니다. Micron · BOE · CSOT · Samsung Display 모두 RAG + 온프렘 + 사인오프 게이트라는 동일 골격. 검증된 small-model 위에 LLM을 얹는 순서.
⑤ 공개 KPI는 4단계 신뢰도로 가중치를 두고 읽어야 한다. Tier A (IR · 학회) · B (장비 벤더 백서) · C (독립 보도) · D (자사 PR). 같은 "+30%"라도 출처에 따라 무게가 달라진다.
