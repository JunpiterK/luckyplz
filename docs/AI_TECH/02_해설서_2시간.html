1. 가장 먼저 알아야 할 5개 용어

이 다섯 단어를 정확히 구분하면 나머지 본문이 훨씬 잘 읽힙니다. 일상에서 혼용하기 쉬운 단어들이지만 각자 다른 의미를 가지고 있습니다.

FAB 팹 — 양산 라인 (Fabrication Facility)

반도체 칩이나 디스플레이 패널을 대량으로 생산하는 공장. "fabrication"의 줄임말. 한 라인에서 수만 장의 wafer / 패널이 동일한 공정을 거쳐 나옵니다.

레시피 책으로 빵을 굽는 공장 — 똑같은 결과를 수만 번 반복해야 한다.

AI 인공지능 — Artificial Intelligence

컴퓨터가 데이터에서 패턴을 발견하고 그 패턴을 새 입력에 적용해 답을 내는 능력의 총칭. 사람이 명시적으로 모든 규칙을 코딩하지 않아도 컴퓨터가 "추론"하는 것이 핵심.

사람이 경험으로 "이건 불량 같다"고 직감하는 것을 컴퓨터가 데이터로 흉내내는 것.

ML 기계학습 — Machine Learning

AI를 구현하는 주류 방법. "규칙을 사람이 직접 코딩하지 않고, 데이터에서 자동으로 학습한다"가 핵심. 오늘날 AI라는 말의 90% 이상은 사실상 ML을 의미합니다.

요리책 레시피를 외우는 게 아니라, 손님 평을 보고 양념 비율을 스스로 조정하는 셰프.

알고리즘 Algorithm — 문제를 푸는 방법의 청사진

"어떻게 풀 것인가"의 설계도·절차. CNN · Transformer · Q-learning 같은 이름이 모두 알고리즘. 코드로 짜기 전, 데이터를 적용하기 전의 추상적 청사진.

"빵을 만드는 방법" 그 자체. 재료(데이터) 없이 방법만 있는 상태.

모델 Model — 알고리즘에 데이터를 적용한 결과물

알고리즘이 특정 데이터셋으로 학습을 마친 결과물. 알고리즘은 청사진이고 모델은 그 청사진으로 만들어진 완성품. 같은 알고리즘이라도 다른 데이터로 학습하면 다른 모델이 됩니다.

레시피(알고리즘)를 따라 실제로 구운 빵(모델). 같은 레시피라도 재료가 다르면 다른 빵이 나온다.

핵심 구분 "CNN을 적용했다"고 하면 알고리즘 이야기. "이 모델이 정확도 95%이다"라고 하면 학습 결과물 이야기. SK hynix의 CNN과 TSMC의 CNN은 같은 알고리즘이지만 학습 데이터가 달라 서로 다른 모델입니다.

2. 팹은 무엇을 만드는 곳인가

AI 적용 사례를 이해하려면 팹의 흐름을 단순화해서 알아두면 됩니다. 반도체 팹과 디스플레이 팹은 만드는 것이 다르지만 운영 방식은 거의 같습니다.

2.1 반도체 팹 vs 디스플레이 팹

2.2 두 팹의 공통 핵심 단어

Wafer / Substrate

처리되는 원판. 한 번에 처리되는 최소 단위. 반도체는 원형 Si, 디스플레이는 사각 Glass.

Mask / FMM

"어디에 무엇을 그릴지"를 정의하는 형판. 반도체는 EUV 마스크, 디스플레이 OLED는 FMMFine Metal Mask, 정밀 금속 마스크.

Chamber

실제 공정이 일어나는 장비 안의 진공·반응 공간. 한 라인에 같은 모델 챔버가 수십 대 있는 게 보통.

Recipe

"이 step에서 어느 조건으로 처리할지"를 정의하는 처리 조건표. 온도·압력·시간·가스 유량 등.

Yield (수율)

처리한 wafer/패널 중 양품 비율. 사업의 핵심 지표. 1%p 변화가 분기 매출 수십~수백억을 움직임.

Lot

같은 그룹으로 처리되는 wafer 묶음. 반도체는 보통 25장 단위. 같은 lot은 같은 recipe로 같은 chamber에서 처리.

3. 팹 운영 5대 개념 — FDC · APC · VM · ADC · PdM

이 5개 약어는 fab AI 자료에서 거의 모든 페이지에 나옵니다. 각각이 무엇이고 어떻게 연결되는지 한 번 짚어두면 사례 읽기가 훨씬 수월합니다.

FDC 결함 탐지·분류 — Fault Detection & Classification

장비 센서에서 나오는 시계열 데이터(온도·압력·RF power 등)에서 이상을 찾아내고 분류하는 시스템. 전통적으로는 SPCStatistical Process Control, 통계적 공정 관리의 통계적 임계값을 썼고, 최근에는 ML 기반 anomaly detection이 추가됨.

병원 모니터의 심전도 알람 — 정상 패턴에서 벗어나면 경보를 울린다.

APC 고도 공정 제어 — Advanced Process Control

"이전 wafer/lot의 측정 결과로 다음 처리 조건을 미세 조정"하는 closed-loop 제어. 가장 단순한 형태가 R2RRun-to-Run, 공정 간 피드백이며, EWMAExponentially Weighted Moving Average, 지수 가중 이동 평균 같은 통계 기법이 전통 표준.

자동차의 크루즈 컨트롤 — 속도가 살짝 떨어지면 가속 페달을 자동으로 살짝 밟는다.

VM 가상 계측 — Virtual Metrology

"실제로 측정하지 않은 wafer의 출력값(두께, CDCritical Dimension, 임계 치수 등)을 센서 데이터만으로 추정"하는 ML 모델. 실측은 비싸고 느려서(5-25 wafer 당 1회), 그 사이를 추정으로 메우는 것이 목적.

자동차 연비를 매번 측정하지 않고, 주행 패턴 데이터로 추정하는 것.

ADC 자동 결함 분류 — Auto Defect Classification

검사 장비가 찾아낸 결함 이미지(SEMScanning Electron Microscope, 주사 전자 현미경·AOIAutomated Optical Inspection, 자동 광학 검사)를 자동으로 클래스(scratch · particle · short 등)에 배정. 전통적으로는 사람 운영자가 했고, 지금은 CNN이 표준.

우체국 우편번호 자동 인식 — 같은 원리로 결함 사진을 자동 라벨링.

PdM 예지 보전 — Predictive Maintenance

"고장 나기 전에 예측·대응"하는 유지보수 전략. 시간 기반 정기 점검(PM)도, 임계값 넘어서 출동(CBM)도 아닌, ML로 향후 고장 시점을 예측해 사전 조치.

차량 점검등이 켜지기 전에 주행 패턴으로 미리 정비소에 가는 것.

3.1 5개 개념이 어떻게 연결되는가

핵심 흐름 센서 → FDC/VM/ADC가 각각 신호·예측·분류를 만들어 → APC가 그것을 받아 다음 lot의 recipe를 보정 → 다음 lot이 조정된 조건으로 처리. PdM은 이 흐름과 별도로 장비 자체의 건강을 모니터링.

4. AI · ML · 알고리즘 · 모델 — 다시 짚기

Part I에서 한 번 짚었지만, AI 사례를 본격적으로 읽기 전에 한 번 더 분명히 해두는 것이 좋습니다.

"이 회사는 AI를 적용했다"는 정확히 무슨 뜻인가?

거의 항상 "머신러닝(ML) 기반의 모델을 운영에 투입했다"는 의미입니다. 더 구체적으로는 — ① 어떤 알고리즘(CNN, Transformer 등)을 골라, ② 사내 데이터로 학습시켜 모델을 만들고, ③ 그 모델을 운영 시스템(APC, ADC, FDC)에 연결한 것입니다.

"우리 모델은 정확도 95%"라는 수치는 어떻게 읽어야 하나?

3가지를 같이 봐야 합니다 — ① 어느 데이터셋에서의 정확도인가 (학습/검증/외부?), ② 학습 데이터와 운영 데이터의 분포가 같은가 (drift 여부), ③ 인간 비교는 어떤가. 운영 환경에서는 학습 시점의 정확도가 시간이 지나며 떨어지는 경우가 많아, 정확도 단일 수치만으로는 부족합니다.

"같은 알고리즘인데 왜 회사마다 결과가 다른가?"

CNN이라는 알고리즘은 같아도, 학습한 데이터(SK hynix 결함 vs TSMC 결함)와 데이터 라벨링 정책(같은 결함을 다르게 정의)이 다르면 결과가 다른 모델이 만들어지기 때문입니다. 알고리즘 = 청사진, 모델 = 청사진 + 데이터 = 완성품 — 이 비유를 다시 떠올리세요.

5. AI가 푸는 3가지 문제 — 분류 · 회귀 · 행동

fab에서 마주치는 거의 모든 AI 문제는 이 셋 중 하나입니다. 어떤 유형인지 먼저 파악하면 적합한 알고리즘이 자연히 좁혀집니다.

분류 — Classification "이게 무엇인가?" — 미리 정해진 카테고리 중 하나로 배정

입력을 받아 정해진 라벨 중 하나로 답을 냅니다. fab 예시 — ADC: SEM 결함 사진 → "scratch / particle / short / open" 중 하나로 자동 분류.

우체국 자동 분류기 — 우편물 사진을 보고 어느 지역으로 보낼지 결정.

대표 알고리즘 → CNN (이미지) · ViT (이미지) · LLM (텍스트 분류)

회귀 — Regression "얼마나?" — 연속적인 숫자를 예측

입력을 받아 연속 변수(두께, 가격, 시간 등)를 예측합니다. fab 예시 — VM: chamber 센서 시계열 → "이 wafer의 두께는 8.7nm"라고 추정.

택시 기사가 출발지 정보로 도착시간을 추정하는 것 — 정해진 카테고리가 아닌 연속 숫자.

대표 알고리즘 → PatchTST · iTransformer · LSTM · GBT (XGBoost)

강화학습 — Reinforcement Learning (RL) "어떻게 행동할까?" — 시행착오로 행동 정책 학습

현재 상태를 보고 다음 행동을 선택. 행동의 결과로 받는 보상으로 정책을 학습. fab 예시 — APC: chamber 상태 → "온도를 +0.5℃ 조정". 단, 양산 적용은 매우 신중해야 함 (탐험 비용 + 안전 제약).

아이가 자전거 타기를 배우는 과정 — 넘어지면(보상 −) 다음번엔 다르게 시도. 무수한 시행착오로 정책 학습.

대표 알고리즘 → DQN · PPO · CQL (Offline) · DreamerV3

4번째 유형 — 생성 (Generation) 위 3가지에 더해 "새로운 데이터를 만드는 것"이 한 카테고리. Diffusion으로 결함 이미지 합성, LLM으로 8D 보고서 작성 등이 여기 속함. Ch.7에서 다룹니다.

6. 신경망이 무엇이길래 모든 곳에 등장하나

최근 10년간 AI의 거의 모든 발전(이미지 인식, 음성 인식, 번역, ChatGPT 등)이 신경망(Neural Network)이라는 같은 구조의 변형에서 나왔습니다. CNN · Transformer · LLM 모두 신경망을 깊게·넓게 변형한 것일 뿐입니다.

6.1 신경망의 본질 — 한 줄 요약

신경망이란 "곱하기 + 덧셈 + 비선형"의 반복. 수억 개 가중치(weight)를 데이터로 자동 조정하는 함수 근사기. 학습이란 곧 가중치를 조정하는 일.

6.2 학습이란 무엇인가

위 그림에서 가운데에 있는 w = 0.42가 핵심입니다. 신경망에는 이런 가중치가 수만~수천억 개 있고, 처음에는 무작위 값으로 시작합니다. 학습 과정은:

  1. 예측 시도: 현재 가중치로 입력을 처리해 ŷ을 출력
  2. 오차 계산: ŷ과 실제 정답 y의 차이 (loss)
  3. 역전파(backpropagation): 오차를 출력층에서 입력층 방향으로 거꾸로 흘려, 각 가중치가 오차에 얼마나 기여했는지 계산
  4. 가중치 조정: 기여도에 따라 모든 가중치를 약간씩 수정 (gradient descent)
  5. 위 1~4를 수만~수억 번 반복
비유 요리사가 손님 평을 보고 "다음번엔 소금 0.42g 더, 후추 0.18g 빼야겠다"는 식으로 레시피(가중치)를 미세 조정하는 것 — 이게 신경망 학습입니다. 단지 가중치가 수억 개일 뿐.

7. 알고리즘 8 가족 — 무엇을 위한 도구들인가

신경망의 변형이 너무 많으니 큰 가족 8개로 묶어 두는 것이 사례를 읽기 좋습니다. 이 8개 안에서 16개 사례 모두가 변형됩니다.

8. 원본 알고리즘이 양산에 들어올 때 — 3가지 변형

학술 논문의 알고리즘을 양산 라인에 그대로 쓰는 회사는 없습니다. 거의 모든 사례에서 다음 3가지 변형이 따라옵니다.

8.1 변형 ① — 도메인 적응 (Backbone 동결)

사전학습된 일반 모델(ResNet, DINOv2)의 대부분을 동결하고 마지막 layer만 fab 데이터로 미세조정. 왜? 라벨이 적은 fab 데이터로도 성능을 살리기 위해. 1만 장 라벨이 100장으로 줄어드는 효과.

대표 사례 Intel ADC · Applied ExtractAI · KLA Multi-Perspective

8.2 변형 ② — 불확실성 정량화

단일 점 예측이 아닌 예측값 + 신뢰구간을 동시에 출력. Bayesian Last Layer · Deep Ensemble · Heteroscedastic loss 셋 중 하나가 표준.

왜? APC가 "이 예측을 믿어도 되는지"를 판단해야 함. VM이 "두께 8.7nm" 한 점만 출력하면 APC는 그 값을 그대로 따라가지만, "8.7nm ± 0.3"이라고 출력하면 APC가 신중해질 수 있음. 잘못된 자신감은 lot 손실로 직결.

대표 사례 SK hynix Panoptes (Bayesian LL) · Gauss Labs SPIE 2024 발표

8.3 변형 ③ — 안전 제약 + 섀도우 배포

학습된 정책이 recipe 안전 범위를 절대 넘지 못하게 hard constraint. 처음엔 추천만 출력하는 섀도우 모드로 배포 후 단계적 승격.

왜? 양산 라인은 PoC가 아님. 한 번의 실수가 lot 손실 · 신뢰 상실로 이어짐. 검증 없이 prod APC에 ML이 들어가면 drift 시 사고.

대표 사례 LG Display Mura RL · Intel n-i to n APC · 모든 RL 사례

핵심 "최신 SOTAState-of-the-Art, 최첨단 모델 = 양산 적합 모델"이 아닙니다. 정확도 1%를 더 얻는 것보다 uncertainty가 정직하고 안전 제약이 들어간 모델이 양산에 들어갑니다.

배경

메모리 fab의 증착(CVD/PVD)·식각 공정은 nm 단위 두께가 수율을 결정합니다. 인라인 메트롤로지in-line Metrology, 라인 안에서의 직접 측정는 비싸고 느려서 보통 5-25 wafer 당 1회만 실측됩니다. 그 사이 처리되는 wafer는 "옛날 측정값"으로 만든 recipe로 제어됩니다 — 결과적으로 APC가 옛날 정보로 지금을 제어하게 됩니다.

사례 2 · Intel "n-i to n" APC + ML 누적 13년 Tier B

US"AI 한 방"이 아닌 누적 전략의 교과서

D1X (Hillsboro) · Fab 42 (Chandler) · 2018-2024 IT@Intel 백서 시리즈

이 사례가 답하는 질문

"AI를 양산에 들이려면 한 번에 큰 모델을 들이는 게 좋을까, 아니면 작은 모델을 누적해 나가는 게 좋을까?"

배경

전통 R2RRun-to-Run, 공정 간 피드백는 n-1 lot의 측정값으로 n+1 lot을 보정합니다. 그 사이 lot n은 보정을 못 받고, 5nm 이하 노드에서는 그 시간차가 곧 수율 손실로 이어졌습니다. Intel의 해법은 n-2, n-3 lot 데이터까지 ML로 통합해 lot n에 즉시 보정 적용.

n-i to n 의미

Intel 공식 커뮤니티 표현: "Data from n-i steps is used to control the process at step n through machine learning."

적용 — 7개 축의 ML 프로그램

  1. CNN ADC — SEM 결함 자동 분류 (2018)
  2. Generative FA (GFA) — wafer map long-tail 결함 합성 (2020)
  3. n-i to n APC ML — 다중 lot 통합 회귀 (2021)
  4. Equipment Health Monitoring — 시계열 anomaly (2022)
  5. Recipe Bayesian Optimization — 신규 recipe 자동 탐색 (2023)
  6. Lot Dispatching RL — 우선순위 결정 (2023)
  7. LLM Co-pilot — SOP/ECN 검색 + 8D 초안 (2024)

전략 — "한 도메인씩 정복"

Intel은 13년에 걸쳐 한 도메인씩 ML 모델을 누적했습니다. 2018년 ADC가 안정된 후 GFA, 그것이 자리잡자 APC ML, … 이런 식. 한 번에 모든 영역에 들이지 않은 것이 핵심.

결과 KPI

  • 2018-2023 누적 절감 $1B+ (Intel IR 발언)
  • ADC 처리량 3-7×, 엔지니어 라벨링 부담 ↓
  • R2R 변동성 20-40% 감소 (Fab 42, 2021)

교훈

  • "AI 한 방"보다 13년 누적 — 모든 사례가 같은 MLOps + Feature Store 기반 위에 서 있음. 그 기반이 진짜 자산.
  • 분기마다 ROI 보고 — 사내 IT/엔지니어링 베스트프랙티스를 매년 백서로 외부 공개. 외부에 가장 투명한 fab AI 프로그램.
  • AI 성과는 사업 언어로 — % 정확도가 아니라 "$1B 절감"으로 말할 때 조직이 움직임.

사례 3 · TSMC HGT 기반 수율 RCA Tier B

TW그래프 신경망으로 수율 원인을 찾는다

Hsinchu Fab 12/15/18 · IEDM 2022 / 2023 발표

이 사례가 답하는 질문

"한 lot이 1500개 step을 거치며 수십 개 chamber를 통과할 때, 어느 chamber의 어느 step이 수율 저하를 일으켰는지 어떻게 찾을 수 있을까?"

전통 방식과 그 한계

전통 SHAPSHapley Additive exPlanations, Shapley 값 기반 설명-on-XGBoost는 "feature 간 상관"은 잡지만 "lot이 어느 chamber 그래프를 통과했나"의 구조는 못 잡습니다. chamber 정보를 단순 one-hot 변수로 처리하니, 같은 chamber 모델끼리의 관계나 흐름 정보가 사라집니다.

적용 — HGT (Heterogeneous Graph Transformer)

베이스라인
XGBoost + SHAP
chamber/tool 정보를 one-hot 변수로
feature 간 상관만 잡음
→
적용
HGT (Heterogeneous Graph Transformer)
· 노드 타입(chamber/tool/recipe/lot) 별 attention head 분리
· Edge에 lot 통과 시간 정보(time-aware)
· Yield를 lot 노드의 supervised target
· Attention weight 시각화로 RCA

HGT가 왜 강한가

fab은 본질적으로 이질 그래프(heterogeneous graph)입니다. chamber, tool, recipe, lot은 서로 다른 종류의 노드이고, 각 관계도 의미가 다릅니다. HGT는 노드/엣지 타입별로 별도의 attention parameter를 학습하기 때문에, 이런 이질성을 모델 안에서 직접 다룰 수 있습니다.

결과 KPI

  • 3nm 양산 첫 분기 yield ramp 이전 노드 대비 30%+ 가속 (TSMC 2024 IR Day)
  • RCA 시간 일 단위 → 시간 단위 (IEDM 2023 발표)
  • Hsinchu Fab 18(3nm) 양산 적용 후 Tainan Fab 18(2nm) 확장 검토

교훈

  • fab은 본질적으로 그래프 — 1500 step이 수십 chamber를 거침. 이 구조 자체를 모델에 입력하면 RCA 정확도가 자릿수 차이로 향상.
  • 학회 발표 의무가 TSMC AI의 비밀 — 사내 기술이 외부 검증을 받아야 진짜 자산.
  • AI 전용 R&D 그룹이 누적 자산을 만든다 — 일회성 PoC와는 다름.

사례 5 · NVIDIA cuLitho × TSMC · Samsung · ASML Tier A

USTWEUEUV 마스크 보정 시간을 2주 → 8시간으로

2023.03 GTC keynote 첫 발표 → 2024 GTC 양산 적용

이 사례가 답하는 질문

"7nm 이하 EUV 노광에서 마스크 한 장 보정에 CPU 수만 코어 × 2주가 걸린다. 이 비용을 줄이지 않으면 2nm는 경제적으로 불가능하다. 어떻게 풀까?"

OPC가 무엇인가

OPC 광학 근접 보정 — Optical Proximity Correction

EUV 노광 시 마스크 패턴이 wafer에 그대로 그려지지 않는 광학적 왜곡을 미리 보정하는 시뮬레이션. 마스크 패턴을 일부러 왜곡시켜 wafer에는 의도한 패턴이 나오게 만드는 기법.

사진 인쇄 시 잉크 번짐을 예상해서 글자를 미리 약간 가늘게 만드는 것 — 단, 수십억 픽셀에 대해 동시에.

cuLitho의 3가지 변형

  • ① GPU 라이브러리화 — lithography 시뮬레이션의 핵심 연산(Hopkins integral, FFT)을 CUDA로 재구현. 500 CPU = 1 H100 GPU 수준 가속.
  • ② ML-Augmented OPC — CNN으로 OPC 결과를 직접 예측하는 보조 모델. 시뮬레이션 결과를 학습 데이터로 활용.
  • ③ EUV Stochastic Modeling — photoresist의 photon shot noise를 score-based generative model(Diffusion 원리)로 학습. ASML 협업.

결과 KPI

  • OPC 처리 시간 2주 → 8시간 (NVIDIA GTC 2024)
  • 전력 소비 ~10% 수준으로 (수만 CPU vs 수백 GPU)
  • 2nm 노드 마스크 보정의 경제적 실용화

배포

2023년 3월 GTC에서 NVIDIA가 처음 발표 (TSMC, Samsung, ASML, Synopsys 동시 참여). 1년 만에 산업 표준 진입 — 2024년 GTC에서 TSMC가 양산 도입 발표. Samsung도 cuLitho 활용 발표.

교훈

  • 인프라 기술이 양산 가능 노드를 결정 — 알고리즘이 아니라 GPU 가속이라는 인프라 자체가 새 노드의 경제성을 만든다.
  • 학술 알고리즘(Diffusion) → 산업 도구 — score-based generative model이 EUV stochastic 모델링에 그대로 적용. 학계와 산업의 거리가 짧아지는 추세.

이 사례가 답하는 질문

"수십 년 누적된 사내 SOP·ECN·8D·프로젝트 보고서가 PPT/Excel/Word/PDF로 EDM에 흩어져 있고, FDC 데이터·MES 업무 이력·일반 사내 정보는 또 별도 시스템에 있다. 한 화면에서 자연어로 다 조회할 수 있을까?"

배경

전통 EDM은 텍스트 키워드 검색만 가능. PPT 표나 Excel 셀 안의 수치, 그림 안의 도식 정보는 검색되지 않습니다. 또한 사용자는 같은 정보를 얻기 위해 EDM, FDC 시스템, MES를 각각 따로 들어가야 했습니다.

적용 — 5단계 구조

베이스라인
전통 EDM 텍스트 키워드 검색
+ 부서별 자료 사일로
+ PPT/Excel 안 콘텐츠 검색 불가
→
적용
IBM Watson + EDM 자동 벡터화 + 프로젝트별 RAG + 멀티-소스 오케스트레이터

핵심 차별점

  • EDM 자료 자동 변환 파이프라인 — 사내 누적 PPT/Excel을 자동으로 PDF로 통일 변환 후 벡터화. 다른 글로벌 사례에는 없는 차별점.
  • 프로젝트·아이템 단위 독립 인덱스 — 권한 체계와 1:1 매핑. 부서별·프로젝트별 접근 제어가 인덱스 단위에서 자동 적용.
  • 멀티-소스 오케스트레이션 — 벡터 DB뿐 아니라 FDC·MES·SOP DB도 통합. 한 자연어 질문으로 모든 사내 정보 조회.

운영 원칙

· 레시피·안전 임계값 자동 변경은 절대 LLM에 위임 금지 — 모든 작업 출력은 엔지니어 사인오프 필요
· 보안: 사내 IP 자료가 외부로 유출되지 않도록 on-prem Watson 배포
· 신뢰성: 답변 시 출처 문서·페이지를 함께 표시 (citation grounding)
· 권한: 프로젝트·아이템 단위 인덱스가 부서별 접근 권한 체계와 일치

글로벌 동종 패턴과 비교

같은 RAG + 오케스트레이션 패턴이 — Micron Engineer Co-pilot, BOE Blue Whale + ADM/AYM, TCL CSOT X-Intelligence 3.0 — 에도 보입니다. Samsung Display의 차별점은 "기존 EDM 자료의 자동 변환 + 프로젝트·아이템 단위 RAG"입니다.

출처 · 사내 진행 자료. KPI는 단계 도입 후 별도 공개 예정.

9. 도입 시 함정 12선

16건 사례에서 반복적으로 나타나는 실패·후회 패턴을 정리했습니다. 다른 회사의 실수를 무료로 학습하는 자료입니다.

  1. 라벨 거버넌스 없이 시작 — 결함 taxonomy가 팀마다 다르면 모델 앙상블이 작동하지 않음. 첫 주에 라벨 정의 위원회부터.
  2. APC 직접 꽂기 — 섀도우 배포 없이 prod APC에 VM 연결 시 drift 때 사고. 최소 1-3개월 병행.
  3. Train/Serve Skew — 피처 계산이 학습과 추론에서 다르게 구현됨. Feature Store로 통일.
  4. Random split CV — 시간 관련 데이터를 무작위 분할 → 누수. 반드시 time-aware CV.
  5. 챔버 무시 — 같은 모델 챔버 10대를 하나로 학습 → drift. 챔버별 fine-tune 필수.
  6. PM event 미포함 — PM 전후 신호 분포가 다름. PM 이벤트를 feature로 명시 주입.
  7. Uncertainty 무시 — 점 추정만 쓰면 APC가 극단 예측을 따라감. Bayesian LL 혹은 Deep Ensemble 필수.
  8. 라벨 편향 — "운영자가 쉬운 것만 라벨"하면 모델이 어려운 클래스에 약해짐. Active Learning으로 balance.
  9. 너무 큰 모델 — Swin-T 써도 생산에선 ResNet-50 + Attention Head로 충분한 경우 다수. 지연·비용 균형.
  10. 엔지니어 패스 없이 LLM 자동화 — 레시피 변경은 반드시 사람 사인오프. Hallucination환각, LLM이 그럴듯한 거짓을 만드는 현상은 반드시 발생.
  11. 합성 데이터 오염 — GAN/Diffusion 이미지가 검증셋에 섞이면 메트릭 부풀려짐. provenance 태깅 의무화.
  12. 플랫폼 선투자 없이 모델 선배포 — 한 모델은 성공할 수 있어도 10개째부터 MLOps 부재로 무너진다.

10. 핵심 메시지 정리

1. 알고리즘과 모델은 다르다. 알고리즘 = 방법(레시피), 모델 = 데이터로 학습된 결과물(빵).
2. VM + APC가 양산 적용의 가장 측정 가능한 앵커. SK hynix Panoptes의 variability −29%가 대표.
3. 학술 모델은 그대로 양산에 안 들어간다. ① 도메인 적응 ② 불확실성 정량화 ③ 안전 제약 — 3가지 변형 필수.
4. LLM은 오케스트레이터, 대체재가 아니다. Micron · BOE · CSOT · Samsung Display 모두 RAG + 온프렘 + 사인오프.
5. 공개 KPI는 4단계 신뢰도로. Tier A (IR · 학회) > B (장비 벤더 백서) > C (독립 보도) > D (자사 PR).
